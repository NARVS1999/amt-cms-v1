# Phase 01.1: Loading and Progress UI — Context

**Gathered:** 2026-07-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Add loading states, page transition indicators, and validation progress feedback across the admin panel. Covers skeleton loading, branded page transition overlay, inline form validation feedback, toast notifications, and destructive confirmation modals. Admin panel only — public site loading deferred to a later phase.

Based on UI-SPEC (01.1-UI-SPEC.md) and validated sketch findings (sketch-findings-amt-v2).

</domain>

<decisions>
## Implementation Decisions

### Component Architecture

- **D-01:** Components live in `components/ui/` — consistent with existing shadcn pattern. Skeleton.tsx, toast.tsx, spinner.tsx alongside button.tsx, card.tsx.
- **D-02:** Skeleton component — use shadcn Skeleton from base-nova registry (includes pulse animation out of the box).
- **D-03:** Spinner component — hand-rolled using Lucide `LoaderCircle` icon with `animate-spin` class. Sizes: sm (14px), default (20px), lg (28px). ARIA: `aria-hidden="true"` with `sr-only` "Loading..." for screen readers.
- **D-04:** Progress bar — use shadcn Progress from base-nova registry (handles ARIA attributes: `role='progressbar'`, `aria-valuenow`).

### Page Transition Implementation

- **D-05:** Route detection via client component with `usePathname` hook — wrap admin layout in a `RouteChangeLoader` component. Next.js-native, no external libraries.
- **D-06:** Overlay covers content area only (not sidebar). Sidebar stays visible and interactive during navigation.
- **D-07:** Overlay uses absolute positioning within the content area (not fixed to viewport). Stays within layout boundaries, no z-index conflicts.
- **D-08:** Animation — branded 3-dot bounce (staggered 0.2s delays) in brand red (#FF0000) on semi-transparent white (rgba(255,255,255,0.9)) background. Dot sizes: 12px each. Label: "Loading".

### Toast/Notification System

- **D-09:** Hand-roll with CSS + React context provider. No external library. ToastProvider wraps admin layout, useToast() hook to show toasts from anywhere.
- **D-10:** Toast variants: success (green background, white text), error (red background, white text), info (dark background, white text). Toast position: bottom-right, fixed.
- **D-11:** Success toasts auto-dismiss after 2 seconds. Error toasts require manual dismiss (× button).

### Form Feedback

- **D-12:** Validation errors appear below inputs in small red text (`font-size: 0.75rem`, `color: var(--color-danger)`). Inputs show error state via `border-color: var(--color-danger)`.
- **D-13:** API errors shown in top-of-form alert banner (`bg-destructive/10`, `role="alert"`).
- **D-14:** Button loading state — text swap to context-specific copy ("Saving...", "Signing in...", "Uploading...") + disabled state.

### Public Site Scope

- **D-15:** This phase covers admin panel only. Public site loading states deferred to later phase.

### Destructive Confirmations

- **D-16:** Modal dialog pattern with resource name, Cancel/Delete buttons. Delete button styled with `bg-destructive` (`--color-danger`). Confirmation copy: "Delete this {resource}? This cannot be undone."

</decisions>

### Reusable Assets
- `apps/frontend/components/ui/` — Existing shadcn components (button, card, input, label, table, alert-dialog). AlertDialog can be used for destructive confirmations.

### Established Patterns
- Animation: shadcn components use Tailwind's `animate-pulse` and `transition-all` patterns
- Admin layout: Content area is padded (`padding: 32px`), sidebar is fixed width (220px)
- Current skeleton usage: Dashboard page and media page already use `animate-pulse` + `bg-muted` div blocks — standardize these into a shared Skeleton component

### Integration Points
- Route loading overlay: Inject `RouteChangeLoader` into the admin layout (`apps/frontend/app/admin/layout.tsx`)
- Toast provider: Wrap admin layout in `ToastProvider` at the same level
- Skeleton component: Replace existing inline skeleton blocks in dashboard and media pages with the shared Skeleton component

<specifics>
## Specific Ideas

- Page transition overlay should fade in/out with 0.3s ease timing
- Skeleton animation pulse timing: 1.8s ease-in-out
- Toast slide-in animation: 0.25s ease from right
- Error toasts should not auto-dismiss — user must manually dismiss
- Overlay should be `aria-hidden="true"` (decorative only)

</specifics>
