**Goal:** End-to-end slice delivering team member photo upload/remove and the missing pricing-plans admin route. Covers backend controller changes, new API route, and frontend UI for both.

## Tasks

### Task 1: Add photo handling to TeamMemberController

<read_first>
- apps/backend/app/Http/Controllers/Api/TeamMemberController.php
- apps/backend/app/Models/TeamMember.php
- apps/backend/app/Http/Controllers/Api/BlogPostController.php (reference pattern for file upload)
</read_first>

<action>
1. In `TeamMemberController@store`: add `'photo' => 'nullable|file|mimes:jpeg,png,webp'` to validate call. After `TeamMember::create($data)`, check `$request->hasFile('photo')` and call `$member->addMediaFromRequest('photo')->toMediaCollection('photo')`. Return fresh resource with `->load('media')`.
2. In `TeamMemberController@update`: do NOT add photo validation or handling — update is JSON-only. Photo changes must go through dedicated endpoints (steps 3-4).
3. Add a new `removePhoto(TeamMember $teamMember)` method: `$teamMember->clearMediaCollection('photo')` then `return $this->success(new TeamMemberResource($teamMember->load('media')))`.
4. Add a new `uploadPhoto(TeamMember $teamMember)` method: validate `'photo' => 'required|file|mimes:jpeg,png,webp'`. Check if `$teamMember->getFirstMedia('photo')` already exists; if so, return a 422 error `"Remove existing photo first"`. Otherwise call `$teamMember->addMediaFromRequest('photo')->toMediaCollection('photo')` and return `$this->success(new TeamMemberResource($teamMember->load('media')))`.
</action>

</acceptance_criteria>

### Task 4: Build team photo upload/remove UI

<read_first>
- apps/frontend/app/admin/team/page.tsx
- apps/frontend/app/admin/blog-posts/page.tsx (reference pattern for file upload UI)
- apps/frontend/lib/admin-api.ts
</read_first>

<action>
1. Add `import { useToast } from '@/components/ui/toast'` and `import { User, Upload, Trash2 } from 'lucide-react'`.
2. Add state: `photoFile: File | null`, `photoPreview: string | null`, `photoUploading: boolean`.
3. In `handleSave`:
   - **Create (no id):** If `photoFile` exists, use FormData (same pattern as blog posts). Append all text fields + `photo` file. Use POST. If no `photoFile`, use existing JSON-based `createTeamMember()`.
   - **Update (has id):** JSON-only — always use existing `updateTeamMember()`. Do NOT send `photoFile` in the save call. Photo changes handled separately (step 4).
4. Add photo section in the form modal (between Bio and Sort Order):
   - Current photo preview: if `photoPreview` exists show `<img>`, else if `editing.photo_url` exists show that, else show Lucide `User` icon in a circle (per D-03).
   - File input: `<input type="file" accept="image/jpeg,image/png,image/webp">` with onChange handler that sets `photoFile` + `photoPreview` (URL.createObjectURL). Include helper text: "Recommended: 400x400px, JPEG/PNG/WebP" (per D-04, no hard size enforcement).
   - **Blocking check for replace:** When editing an existing member with `editing.photo_url` set and user selects a new file, do NOT set `photoFile`. Instead, show an inline message: `"Remove existing photo first, then upload a new one."` styled with `var(--color-warning)`.
   - Remove button: if `editing.photo_url` exists (and no `photoPreview`), show a "Remove" button (Trash2 icon). On click, calls `removeTeamMemberPhoto(m.id)`, reloads list, shows success toast. After removal, file input becomes available.
   - Upload button (only visible when editing and `photoPreview` is set with no `editing.photo_url`): shows "Upload" button (Upload icon). On click, calls `uploadTeamMemberPhoto(m.id, photoFile)`, reloads list, shows success toast.
5. Add `showToast` calls: success toast after save/upload/remove, error toast on failure.
6. Reset photo state (`photoFile`, `photoPreview`) when opening a new edit or closing the modal.
</action>

<acceptance_criteria>

- Creating a new member with photo uploads via FormData and shows success toast
- Editing an existing member: Save is JSON-only (no photo in save payload)
- Editing with existing photo: selecting a new file shows inline blocking message requiring removal first
- Remove button clears photo via API and updates display to placeholder icon
