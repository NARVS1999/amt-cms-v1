### Task 3: Add inline validation error display to all admin forms

<read_first>
- apps/frontend/app/admin/services/page.tsx
- apps/frontend/app/admin/team/page.tsx
- apps/frontend/app/admin/pages/page.tsx
- apps/frontend/app/admin/pricing-plans/page.tsx
- .claude/skills/sketch-findings-amt-v2/references/form-feedback.md
</read_first>

<action>
1. Add a `validationErrors` state: `const [validationErrors, setValidationErrors] = useState<Record<string, string>>({})` to each page.
2. In the catch block of handleSave, when `e.status === 422`, map `e.errors` to `validationErrors`: a flat `Record<string, string>` using the first error message per field (Laravel returns `{ field: ["msg1", "msg2"] }`). Set the state.
3. Clear `validationErrors` when opening the form (`setValidationErrors({})`) and when closing it.
4. For each `<Input>` or `<textarea>` in the form modal, render an error message below it:
   ```tsx
   {validationErrors['field_name'] && (
     <p className="text-xs" style={{ color: 'var(--color-danger)' }}>{validationErrors['field_name']}</p>
   )}
   ```
5. Apply error border styling to inputs that have validation errors: `className` concat with `'border-red-500'` when `validationErrors['field_name']` is truthy, using the `cn()` utility or inline `style={{ borderColor: 'var(--color-danger)' }}`.
6. Specific fields to cover per page:
   - **Services**: title, description, icon
   - **Team**: name, role, bio
   - **Pages**: title, slug, hero_heading, hero_subtext, sections
   - **Pricing Plans**: name, price, interval, description, cta_text
</action>

<acceptance_criteria>
- Submitting an empty required field → 422 → inline red error text appears below that specific input
- Input with error shows red border (`var(--color-danger)`)
- Multiple validation errors show inline for each respective field
- Opening the form clears previous validation errors
- Submitting with valid data clears all errors
- `npx tsc --noEmit` passes, `npm run build` succeeds
</acceptance_criteria>
