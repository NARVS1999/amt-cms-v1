# Plan 03-04: Blog System Gap Closure

## Goal

Close all 6 diagnosed UAT gaps from Phase 3. These are targeted surgical fixes — no new features, no new endpoints, no schema changes beyond the minimal corrections identified.

## Gaps Addressed

| Gap | Severity | Root Cause | Fix |
|-----|----------|------------|-----|
| G-03-1 | major | HTMLPurifier strips `data:` URIs from Quill-pasted images | Add `data` to URI.AllowedSchemes |
| G-03-3 | major | All BlogPosts default to `sort_order=0`, neighbor lookup fails | Add `booted()` hook for auto-increment |
| G-03-4 | major | Zod `content` required but listing API omits it | Make `content` optional in schema |
| G-03-4b | major | Home link uses `#home` anchor instead of `/` | Change href to `/` |
| G-03-6 | blocker | `generateStaticParams` returns empty array on API failure | Throw when zero posts |
| G-03-7 | minor | LatestPosts returns null when empty array (same root cause as G-03-4) | Fixed by G-03-4 + defensive null check |

## Fix Steps

### Step 1: HTMLPurifier — Allow data: URIs (G-03-1)

**File:** `apps/backend/app/Http/Controllers/Api/BlogPostController.php`

Locate the `sanitizeContent()` method. After the `$config = HTMLPurifier_Config::createDefault();` line, add:

```php
$config->set('URI.AllowedSchemes', ['http' => true, 'https' => true, 'mailto' => true, 'data' => true]);
```

This preserves base64-encoded images that Quill pastes into content while still stripping dangerous protocols.

**Verify:** Run `php artisan test --filter=BlogPost` to ensure no regressions.

---

### Step 2: BlogPost — Auto-increment sort_order (G-03-3)

**File:** `apps/backend/app/Models/BlogPost.php`

Add a `booted()` method to the BlogPost model:

```php
protected static function booted(): void
{
    static::creating(function (BlogPost $post) {
        if (is_null($post->sort_order)) {
            $post->sort_order = (self::max('sort_order') ?? 0) + 1;
        }
    });
}
```

This ensures each new post gets a unique sequential `sort_order`, enabling the swap logic in the admin UI to find neighbors.

**Verify:** Create 2+ posts in admin, click sort arrows — no "Cannot move down further" error.

---

### Step 3: Zod Schema — Make content optional (G-03-4, G-03-7)

**File:** `packages/shared/src/schemas/blog-post.ts`

Change the `content` field from required to optional:

```typescript
// Before
content: z.string(),

// After
content: z.string().optional(),
```

The listing endpoint intentionally omits content (only the show endpoint returns it). Making it optional allows the listing Zod parse to succeed. G-03-7 (LatestPosts empty) is the same root cause — once `fetchBlogPosts` parses correctly, LatestPosts populates.

**Verify:** Run `npx tsc --noEmit` in `apps/frontend` — no type errors.

---

### Step 4: Header — Fix Home link href (G-03-4b)

**File:** `apps/frontend/components/Header.tsx`

Find the Home link (likely `<a href="#home">` or `<Link href="#home">`) and change:

```tsx
// Before
href="#home"

// After
href="/"
```

This makes the Home navigation link navigate to the root homepage on all pages.

---

### Step 5: generateStaticParams — Throw on zero posts (G-03-6)

**File:** `apps/frontend/app/(public)/blog/[slug]/page.tsx`

Locate the `generateStaticParams` function. After fetching posts, add a guard:

```typescript
export async function generateStaticParams() {
  const posts = await fetchBlogPosts();

  if (!posts || posts.length === 0) {
    throw new Error(
      'No blog posts found. Ensure the Laravel API is running during build (npm run build).'
    );
  }

  return posts.map((post) => ({
    slug: post.slug,
  }));
}
```

This gives a clear error message during `npm run build` instead of a silent failure that causes runtime crashes.

**Also verify:** `apps/frontend/lib/api.ts` — the `fetchBlogPosts()` function's catch block should re-throw (or at minimum log) so `generateStaticParams` actually receives the error. If it currently returns `[]` on error, change it to:

```typescript
// In the catch block
console.error('Failed to fetch blog posts:', error);
throw error;
```

**Verify:** Run `npm run build` in `apps/frontend` with API running — builds successfully with posts. Run without API — clear error message.
